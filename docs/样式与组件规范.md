# 样式与组件规范

## 组件职责

- Ant Design：Button、Input、Select、DatePicker、Drawer、Modal、Tooltip、Form、Message 等通用控件。
- Tailwind CSS：`flex`、`grid`、间距、尺寸、定位和响应式布局。
- 项目 CSS：工作项树、甘特图、富文本预览等具有明确业务视觉结构的组件。

不得用大量 Tailwind `!important` 覆盖 Ant Design 内部 DOM。需要统一外观时，优先修改 `ConfigProvider` Token、组件属性或语义化 `classNames/styles`。

业务表单的下拉选择和日期选择必须使用 Ant Design `Select`、`DatePicker`，不得直接使用原生 `<select>` 或 `<input type="date">`。原生控件的弹层由浏览器和操作系统绘制，无法保证与设计系统一致，也无法可靠控制视口边缘定位；仅在明确需要系统原生交互并经过设计确认时例外。

### 表单选择器边界

- 页面级 CSS 不得使用 `label input`、`.form input`、`label textarea` 等宽泛后代选择器统一设置高度、边框、内外边距或布局。这些选择器会命中 Ant Design `Select`、`DatePicker`、`InputNumber`、`AutoComplete` 等组件内部的原生输入节点，造成文字裁切、错位或弹层异常。
- 原生表单控件必须通过业务类名或直接子级限定，例如 `.publish-native-field`、`.form-field > input`，确保样式不会穿透组件库内部结构。
- Ant Design 控件需要统一外观时，依次优先使用 `ConfigProvider` Token、组件属性、语义化 `classNames/styles` 和明确限定到组件根类的项目 CSS；不得依赖组件内部偶然存在的 DOM 层级。
- 引入或替换 Ant Design 表单控件后，必须验证默认值、选中值、聚焦状态、弹层打开状态以及移动端视口边缘表现。

```css
/* 禁止：会覆盖组件库内部 input */
label input {
  min-height: 38px;
  margin-top: 7px;
}

/* 推荐：只作用于页面直接维护的原生输入框 */
.form-field > input {
  min-height: 38px;
  margin-top: 7px;
}
```

## 视觉基准

- 当前已确认页面是迁移期间的视觉基准，不因为引入组件库而整体改成 Ant Design 默认后台模板。
- 页面背景保持冷白和浅灰，不增加装饰性渐变、光斑或大圆角卡片。
- 信息密集页面优先使用表格、列表和抽屉，不使用卡片套卡片。
- 控件文字、行高和固定列宽必须稳定，Hover 状态不得引发布局跳动。

## 设计变量

- 主色：`#4268f6`
- 主文字：`#172033`
- 边框：`#e4e8f0`
- 常用圆角：`6px`

颜色和尺寸应来自 Ant Design Token、CSS 变量或公共常量，不在业务 JSX 中重复硬编码。

## 响应式

- 桌面端优先保证工作项树的扫描效率。
- 小屏幕允许横向滚动数据表，不压缩到不可阅读。
- 抽屉在窄屏使用全宽。
- 所有弹窗、抽屉和日期面板都需要检查视口边缘裁切。
