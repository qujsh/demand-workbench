# 样式与组件规范

## 组件职责

- Ant Design：Button、Input、Select、DatePicker、Drawer、Modal、Tooltip、Form、Message 等通用控件。
- Tailwind CSS：`flex`、`grid`、间距、尺寸、定位和响应式布局。
- 项目 CSS：工作项树、甘特图、富文本预览等具有明确业务视觉结构的组件。

不得用大量 Tailwind `!important` 覆盖 Ant Design 内部 DOM。需要统一外观时，优先修改 `ConfigProvider` Token、组件属性或语义化 `classNames/styles`。

业务表单的下拉选择和日期选择必须使用 Ant Design `Select`、`DatePicker`，不得直接使用原生 `<select>` 或 `<input type="date">`。原生控件的弹层由浏览器和操作系统绘制，无法保证与设计系统一致，也无法可靠控制视口边缘定位；仅在明确需要系统原生交互并经过设计确认时例外。

### 表单选择器边界

- 页面级 CSS 不得使用 `label input`、`.form input`、`label textarea` 等宽泛后代选择器统一设置高度、边框、内外边距或布局。这些选择器会命中 Ant Design `Select`、`DatePicker`、`InputNumber`、`AutoComplete` 等组件内部的原生输入节点，造成文字裁切、错位或弹层异常。
- 原生表单控件必须通过业务类名或直接子级限定，例如 `.publish-native-field`、`.form-field > input`，确保样式不会穿透组件库内部结构。
- Ant Design 控件需要统一外观时，依次优先使用 `ConfigProvider` Token、组件属性、语义化 `classNames/styles` 和明确限定到组件根类的项目 CSS；不得依赖组件内部偶然存在的 DOM 层级。
- 引入或替换 Ant Design 表单控件后，必须验证默认值、选中值、聚焦状态、弹层打开状态以及移动端视口边缘表现。

```css
/* 禁止：会覆盖组件库内部 input */
label input {
  min-height: 38px;
  margin-top: 7px;
}

/* 推荐：只作用于页面直接维护的原生输入框 */
.form-field > input {
  min-height: 38px;
  margin-top: 7px;
}
```

## 视觉基准

- 当前已确认页面是迁移期间的视觉基准，不因为引入组件库而整体改成 Ant Design 默认后台模板。
- 页面背景保持冷白和浅灰，不增加装饰性渐变、光斑或大圆角卡片。
- 信息密集页面优先使用表格、列表和抽屉，不使用卡片套卡片。
- 控件文字、行高和固定列宽必须稳定，Hover 状态不得引发布局跳动。

## 设计变量

- 主色：`#4268f6`
- 主文字：`#172033`
- 边框：`#e4e8f0`
- 常用圆角：`6px`

颜色和尺寸应来自 Ant Design Token、CSS 变量或公共常量，不在业务 JSX 中重复硬编码。

## 字体与信息层级

构想台采用“操作区域紧凑、长内容易读”的排版方式。参考 ChatGPT 设置页与聊天页的阅读层级，保留本项目蓝色强调、白色内容区和原有工作台布局，不照搬其深色主题或页面结构。

以下为当前排版基线，具体页面效果仍可随评审调整；不是全部页面已经逐项达标的验收结论。本规范适用于 B 端构想台，不自动改变 C 端或手机端设计。

### 统一字体来源

- 全局字体在 `src/styles.css` 的 `--font-ui` 中维护，阅读内容使用 `--font-reading`；业务区域优先引用变量，不另设一套字体。
- Ant Design 的 `src/app/providers.tsx` 中 `ConfigProvider` 字体应与全局保持一致，避免表单、弹窗与原生业务组件字体不同。
- 当前使用系统字体栈，不新增网络字体依赖：

```css
--font-ui: -apple-system-body, ui-sans-serif, -apple-system, system-ui,
  "Segoe UI", Helvetica, "Apple Color Emoji", Arial, sans-serif,
  "Segoe UI Emoji", "Segoe UI Symbol";
--font-reading: var(--font-ui);
```

系统字体栈会根据设备及字符选择字体，不能据此声称所有设备都使用同一种中文字体。不要为了模拟参考网站而强行给全站指定某一中文字体。

### 按内容角色设置排版

| 内容角色 | 字号／行高 | 字重 | 适用位置 |
| --- | --- | --- | --- |
| 操作文字 | 14px／20px | 400；名称或选中项可用500 | 导航、按钮、表单标签、工具栏、列表正文 |
| 辅助信息 | 12px／16–18px | 400 | 提示、编号、时间、统计和次要说明 |
| 阅读正文 | 16px／26px | 400 | 需求描述、AI分析、富文本预览、完整任务内容 |
| 页面主标题 | 24px／约29px | 400 | 需求管理、个人设置等页面标题 |
| 区域标题 | 16–18px／24–28px | 500；正文小标题可用600 | 分组标题、面板标题、阅读内容小节 |
| 需求标题输入 | 16px／约23px | 400 | 原始需求标题编辑框 |

- 用字号、间距和颜色建立层级，不通过整段加粗表达重要性。正文中的明确强调可用600，避免默认使用650或700。
- 不新增9–11px的普通操作文字；密集表格优先调整列宽、换行或提供横向滚动，不靠缩小字号解决。
- 阅读段落通常间隔16px；紧凑关联内容可用8px。列表保持层级清晰，不叠加段落和列表外边距造成过大空白。
- 编辑器与只读预览应保持正文的字体、字号、行高及加粗／倾斜／列表语义一致。编辑器占位提示使用相同阅读尺寸，以颜色区分，不默认加粗。
- 保留富文本倾斜的可见效果；如全局禁用字体合成，需要在编辑内容和对应预览的倾斜节点局部允许样式合成，不对全站强制倾斜。

### 控件与留白

- 通用 Ant Design 控件以14px文字、36px高度为基线，通过 Token 维护；紧凑工具栏可采用28–32px按钮，但应保证图标及文字不裁切。
- 阅读编辑区内边距参考上下20px、左右20–22px；表单配置行参考上下12px、左右16px，按业务布局调整，不机械套用到工作项树每一行。
- 保留项目常用6px圆角，不因参考网站使用胶囊按钮或16px容器圆角而全站替换。
- 主要按钮保持蓝色，减少装饰性阴影与渐变；聚焦边框、选中态、危险操作与禁用态仍需清晰可辨。

### 修改与验证边界

- 修改现有语义类或主题 Token，不新增全局 `p`、`label`、`strong` 等标签规则覆盖所有模块，不穿透组件库内部输入节点。
- 新页面按内容角色选择字号，不按旧页面的偶然数值复制，也不要对整个样式文件机械替换字号。
- 第三方嵌入页面（如豆包 iframe）的字体不由构想台样式控制，不承诺与本地编辑区域一致。
- 按测试规范进行验证：试调阶段检查当前桌面页面的真实字体、换行、裁切、溢出和目标交互；定稿时再覆盖需求列表、需求分析、工作项、发布表单、预览和设置等受影响页面。不能将单页验证描述为全站已验收。

## 响应式

- 桌面端优先保证工作项树的扫描效率。
- 小屏幕允许横向滚动数据表，不压缩到不可阅读。
- 抽屉在窄屏使用全宽。
- 所有弹窗、抽屉和日期面板都需要检查视口边缘裁切。
