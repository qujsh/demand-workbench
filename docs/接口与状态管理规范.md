# 接口与状态管理规范

## HTTP 请求

- 页面和展示组件不得直接调用 `fetch`。
- 通用请求处理集中在 `shared/api/httpClient.ts`。
- 功能接口集中在 `features/<功能>/api`。
- 后端响应必须通过 Zod 在网络边界校验，校验完成后才能进入 UI。
- 错误统一转换为 `ApiError`，页面只消费稳定的错误信息和错误码。
- HTTP 成功但响应未通过 Zod 校验时，必须使用 `INVALID_API_RESPONSE` 明确提示前后端版本不一致，不得误报为网络连接失败。
- 后端统一响应 `{ success, msg, errorCode, errorMsg }` 必须在 API 层解包，组件不得直接读取响应外壳。
- 后端英文枚举应在 Schema 边界转换为前端领域值，例如 `high` 转为 `高`、`success` 转为 `SUCCESS`。
- 服务端返回的可空业务字段必须按真实状态展示；例如日期为 `null` 时显示“未设置”，不得为了页面完整而填充虚假日期。

## TanStack Query

- GET 查询使用 `useQuery`。
- 创建、修改和删除使用 `useMutation`。
- Query Key 应包含资源名称和业务 ID。
- 不把 Query 返回结果复制到另一个 State，除非用户正在编辑一份明确的本地草稿。
- 请求取消使用 Query 提供的 `AbortSignal`。

## 异步拆解

```text
useMutation 提交需求文本
  -> 获得 taskId
  -> useQuery 按 taskId 轮询
  -> SUCCESS 或 FAILED 后停止
```

轮询间隔由功能 Hook 管理，页面不得创建自己的 `setTimeout` 轮询链。

## 环境变量

- 前端接口地址使用 `VITE_API_BASE_URL`。
- `.env.local` 只保存本机覆盖值，不提交版本库。
- 所有 `VITE_` 变量都可能被用户在浏览器中看到，禁止配置 DeepSeek Key 或数据库凭证。
