# 系统配置与角色权限

系统配置包含账号管理、角色管理、成长与信用、操作审计，路由分别为 `/system/accounts`、`/system/roles`、`/system/growth`、`/system/audits`。分类管理继续保留既有入口，不在配置中心新增账号或角色页面。

角色管理提供角色列表及公共权限页签。权限由后端提供稳定英文编码、中文名称、分组、说明与是否可配置为公共权限，角色页面以中文为主并补充英文名称，目录页显式展示编码。账号分配使用接口返回的启用角色选项，每个账号可分配多个平台角色。

公共权限自动叠加到所有正常账号，可配置需求管理及分享管理模块访问权限。账号本人资料、密码、安全设置及退出登录是保留能力，不受公共业务权限撤销影响。普通角色不勾选某权限不代表拒绝公共权限；本期不提供拒绝规则。

平台管理员为受保护内置角色，不可编辑或停用；普通用户基础角色和公共权限不可停用，仍关联账号的角色须先迁出账号才可停用。公共权限修改需二次确认，影响所有正常账号。服务端通过事务、共用行锁、版本校验与审计保护授权变更。

前端使用 TanStack Query 查询有效权限，按权限控制菜单、目标路由和分类操作按钮；实际接口仍由后端校验。需求及分享当前按模块授权，需求成员权限、发布资格和内容归属继续生效。工作台、承接管理、交付验收尚无独立可用页面，本期不为预留入口提供虚假的授权项。

角色或公共权限保存、账号角色调整后失效 account 查询缓存；其他会话刷新或窗口聚焦后更新显示。授权未加载完成或加载失败时不渲染受保护业务页面。无需求权限时不发起需求列表请求，个人设置中的需求协作面板也不展示。

数据库通过新增 Flyway `V202611052300__add_configurable_roles_and_common_permissions.sql` 升级。升级保留原角色关系，新增公共业务权限以保留原有业务功能；普通用户不再默认可维护共用分类。

角色配置使用独立页面：新建为 `/system/roles/new`，编辑或查看为 `/system/roles/:code/edit`；公共权限保存后返回 `/system/roles?tab=common`。页面刷新按角色编码加载数据，不依赖列表中的临时选中状态；未知角色显示明确提示。

权限按后端分组组成多列树，桌面三列、中屏两列、手机一列，页面统一滚动。提供中文名称/英文编码搜索、仅看已选、模块全选与半选及展开/收起切换；筛选仅影响展示，不改变已选权限。公共继承项在角色信息下独立展示，“仅看已选”对应角色额外授权。管理员以只读文本及禁用勾选展示，保留展开与搜索能力。

## 权限目录维护

`/system/permissions` 为“系统配置 → 权限管理”，需要 `permissions.manage`。模块和子模块组织层级，操作节点才可分配给角色；支持最多五级模块、排序、启停、中英文名称与说明。中文名称、英文名称、英文编码是三个独立字段，英文编码创建后固定，不能通过改名改变既有代码绑定。

目录管理使用树形表格展示，新增和编辑在响应式抽屉中完成。搜索匹配中英文名称、说明和编码，保留上级路径；匹配模块时展示其下级。角色配置使用相同数据库目录，按模块路径展示中英文权限，新定义可先分配，代码绑定后才对具体菜单、按钮与接口生效；目录不会自动建立接口映射或改变数据归属范围。

内置节点允许编辑中英文文案和排序，编码、类型、上级、启用和公共属性受保护；普通节点可维护层级、状态及公共资格。操作权限被任意非管理员角色（含公共角色）引用时不可停用，模块须先停用子项。取消公共资格前需先移除公共角色的授权。模块本身不可授权，也不可设为公共权限。暂不提供删除或复用编码，停用后保留历史目录。新操作权限自动赋予受保护管理员；其他角色和公共权限不自动获得新授权。

Flyway `V202611070100__create_permission_directory.sql` 创建 `sys_permission`，迁移原有十项权限及三组模块，并增加 `permissions.manage`；仅给管理员补充目录管理权，原有角色/公共授权关系保留。审计摘要扩展为 MEDIUMTEXT，以完整记录双语配置前后内容和大量角色授权。节点编辑、角色分配共用管理员行锁，目录与管理员授权、审计在同一事务提交，编辑需携带版本。

## 统一菜单与权限目录

权限管理采用左侧资源树、右侧详情的独立页面。菜单与权限页签通过「新增菜单 / 权限」选择菜单分组、菜单页面、操作权限；节点快捷入口自动带入所属层级。通用能力页签通过「新增通用权限」独立维护，不建立页面引用关系。

中文名称和英文名称可编辑；稳定英文编码创建后不可修改。详情不提供路由、图标或权限说明编辑，路由及图标由 `navigation.ts` 注册绑定。新增菜单不会生成业务页面，未接入页面点击后显示待开放提示。已绑定页面的导航名称、顺序和可见性由后端实时返回，未授权及空分组不显示。

菜单可见性只控制入口；权限启用状态控制鉴权。页面停用使页面及其操作权限失效，分组停用只隐藏导航组。账号、角色和权限管理三个内置入口受保护。公共授权仍在角色管理中显式勾选，与通用能力定义独立。

分享管理仍以 `shares.use` 控制进入，新增、编辑（含标签）、删除与恢复分别绑定 `shares.create`、`shares.edit`、`shares.delete`。上传还需 `files.upload`；已有账号角色和公共授权在 Flyway 迁移中保留原有能力，随后可逐项调整。

## 账号多角色与状态收敛（2026-11-07）

账号通过 sys_user_role 关联多个角色，角色选择至少一项，不允许分配公共角色或已停用角色。有效权限为所有启用角色权限的去重并集，再叠加公共权限。列表与个人中心展示全部角色，管理区域使用多选。分配后移除某个角色，仅撤销该角色独有的权限；重叠权限继续保留。

账号管理状态仅提供正常 active 和禁用 banned；禁用撤销全部会话，恢复正常不会恢复旧会话。历史 restricted/suspended 账号由 Flyway 迁移为 banned；业务身份状态与注销生命周期保持独立。最后一位正常管理员的保护按是否持有 admin 角色判断，而不是某个展示用主角色。

## 账号管理补齐（2026-11-07）

账号页直接显示搜索筛选和账号表格，移除单一的“账号与角色”标签。支持账号编号/昵称搜索、角色筛选、正常/禁用筛选及服务端分页；筛选变化返回第一页，清空或重置恢复全部账号。注册时间和最近登录时间来自 sys_user，空值显示“暂无记录”。

点击“管理”打开右侧抽屉，显示账号基本信息、角色多选与状态选择，底部统一“取消 / 保存修改”。未修改时禁止保存，关闭有改动的抽屉需确认放弃；禁用需二次确认。没有 roles.manage 时角色只读；注销中的或已注销账号整体只读。

统一保存接口 `/api/v1/admin/users/save` 在同一事务中鉴权、校验、保存角色及状态、撤销禁用账号会话并写入前后值审计，任一失败不会部分更新。分页查询 `/api/v1/admin/users/page` 查询全部未删除账号，不再局限最近100个。搜索将 `%`、`_` 当普通字符处理。

暂不包含新增账号、批量操作、重置密码、账号安全详情及按账号查看审计抽屉；这些需要独立的业务和授权规则，平台审计仍从“操作审计”查看。

多角色审计摘要扩容为 TEXT，保留完整变更前后角色列表，避免合法配置被原有500字字段限制回滚。
