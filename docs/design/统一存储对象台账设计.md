# 通用上传台账：media_upload

## 已确定的简化方案

直接扩展 `media_upload`，不新增空间表、对象表或引用表。原先三表设计已被此方案替代。

通用上传仓储位于后端 `storage` 模块，分享与任务、需求附件共用。

| 字段 | 用途 |
| --- | --- |
| media_no | 全局媒体编号，连接业务媒体表 |
| source_module | 来源模块：requirement / task / share |
| source_business_no | 来源业务编号，允许为空 |
| scene | 上传用途，如 task_cover、requirement_image、share_image |
| bucket / storage_key | 空间与对象稳定位置 |
| object_url | 无签名基础地址，不保存临时 token |
| owner_user_id | 上传者 |
| original_name / mime_type / file_size | 文件元数据 |
| expires_at / completed_at / object_hash | 凭证到期时间、云端确认时间、哈希 |
| physical_deleted_at | 预留物理删除审计时间；当前不执行删除 |
| deleted / created_at / updated_at | 通用审计字段 |

移除 `requirement_no` 列，以 `source_business_no` 代替。任务当前以所属需求编号作为业务编号，因此来源为 task 时也由任务服务校验该需求权限。需求附件来源为 requirement，两者不能与 share 上传混用。

分享先上传后创建记录，来源编号可以为空；一张图片可能关联多条记录，因此不能把来源编号当作全部引用关系。具体关联继续由 share_media、share_record_media、task_media、业务草稿及发布快照负责。

## 写入与核验

- 分享申请上传凭证时，同一事务写入 share_media 和 media_upload；提交成功后返回凭证。
- 分享确认接口先查询云端对象、验证大小和类型，再同一事务保存两表的确认结果。失败整体回滚；重复确认幂等。
- 任务与需求沿用现有上传流程，映射为通用来源字段；未削弱原有权限与媒体引用校验。
- 私有文件访问继续经过后端鉴权，临时签名链接不保存到台账。

## 范围与清理边界

台账登记系统新上传，不自动收录七牛控制台直接上传的对象，不回填旧分享图片。

完成上传仅代表云端核验成功，不代表当前仍被引用。空来源编号、凭证到期、业务进入回收站都不能直接作为物理删除依据。后续清理须检查正式内容、草稿、工作副本、回收站和历史快照；当前不实现自动删除。

迁移文件：后端 `V202611040900__generalize_media_upload_sources.sql`。该迁移重命名来源列、增加模块及物理删除审计字段并重建来源索引；启动后端时由 Flyway 执行。

## 本轮验证

19项针对性测试通过，包括真实MySQL来源列迁移、任务和需求附件上传回归、分享登记与重复确认、台账更新失败时业务媒体同步回滚，以及跨模块上传确认拒绝。测试仅使用隔离MySQL和云存储替身，未修改开发库或实际七牛文件。
