# 分享图片访问与配置

更新：2026-11-04。本轮只调整后端配置与图片授权，不修改CDN、不切换云端空间权限、不新增公开记录页面。

## 展示逻辑

数据库与页面使用稳定入口 `/api/v1/shares/media/content?mediaNo=...`，不保存会到期的七牛签名URL。浏览器首次展示、重新加载或放大图片需要加载资源时访问此入口，后端检查登录会话、图片归属与上传完成状态，返回302到新的短期签名地址；图片字节直接由七牛返回。302响应 `private, no-store`，避免浏览器持久复用旧跳转。

“每次鉴权”是指每次请求这个入口，不是每隔几秒轮询，也不是图片一直显示就一直调用后端。每次入口请求会生成300秒有效的下载授权，用户本人的查看权限不随签名过期而消失；已正常加载的图片无需定时续签，重新请求入口时自然得到新签名。页面不需要保存或更新云端凭证。

## 权限

| 入口 | 允许访问 |
| --- | --- |
| `/media/content?mediaNo=...` | 登录本人，包含本人编辑中的完成图片及回收站保留图片 |
| `/media/public-content?recordNo=...&mediaNo=...` | 可匿名；指定正式记录必须SAVED、PUBLIC、未删除，且确实关联该已完成图片 |

公开入口通过记录媒体关联表校验，不读取编辑草稿，不因为图片曾公开就永久放行，也不能将其他记录编号与图片编号任意拼接。

正式记录切换为PRIVATE或移入回收站后，公开入口的新请求返回404；本人入口仍可使用。已经签发的七牛链接在有效期内可能继续使用，浏览器已加载内容和CDN副本也不会被应用收回。本轮按用户要求不修改CDN配置。

## 配置复用

公有、私有空间分开配置，共享既有账号密钥和上传区域。分享图片默认且固定写入私有空间，即使记录选择公开也不移动文件；公开入口仍按记录权限签发访问地址。

```dotenv
# 公有空间，需求/任务业务使用。
QINIU_PUBLIC_BUCKET=<公有桶名称>
QINIU_PUBLIC_DOWNLOAD_DOMAIN=<公有桶下载域名>
# 分享新图片上传目标，必须填写实际的另一私有空间及对应域名。
QINIU_PRIVATE_BUCKET=<私有桶名称>
QINIU_PRIVATE_DOWNLOAD_DOMAIN=<私有桶下载域名>
# 当前测试域名沿用既有开关；正式域名启用HTTPS。
QINIU_ALLOW_HTTP_TEST_DOMAIN=true
```

后端 `application.yml` 明确提供 `qiniu.public-bucket`、`qiniu.public-download-domain`、`qiniu.private-bucket`、`qiniu.private-download-domain`。已移除重复的 `qiniu.bucket`、`qiniu.download-domain` 别名，公有存储直接绑定 `public-bucket`、`public-download-domain`。旧 `QINIU_BUCKET`、`QINIU_DOWNLOAD_DOMAIN` 环境变量不再使用。

分享模块仍可使用 `SHARE_QINIU_BUCKET`、`SHARE_QINIU_DOWNLOAD_DOMAIN` 覆盖私有目标；不再默认继承公有桶和域名。缺少私有桶或私有域名时，应用仍可启动，但新上传返回明确配置错误，不会写入公有空间。开发阶段不保留历史公有桶读取分支，分享图片上传、核验和下载均只接受当前配置的私有桶。

密钥 `QINIU_ACCESS_KEY/SECRET_KEY` 及上传地址继续复用，不要写入前端VITE环境或提交真实密钥。配置修改后需重启后端。

旧PRIVATE_BUCKET_CONFIRMED标记不再要求填写：它并不能检查实际云端权限。应用不会自动将空间设为私有。若现有空间公开，通过签名入口仍无法阻止别人直接访问公开原地址；是否调整空间访问类型需要在七牛侧处理。不能为了分享私密图片直接改变既有公开附件空间而不检查其影响。

当前显式测试开关允许七牛 `*.hd-bkt.clouddn.com` 的HTTP下载；上传仍为HTTPS，不放开任意HTTP域名。后续配置正式HTTPS域名后可关闭测试开关，CDN回源鉴权与缓存由部署配置处理。
