# 时间线定位与浮窗引用实现

更新：2026-11-03。前端 `demand-workbench`，后端 `demand-workbench-backend`。本轮为已实现内容说明。

## 用户操作

- 工具栏“定位时间”：选择年份、月份，或输入具体日期；按记录发生时间定位。当天没有记录时展示附近日期，并提示用户。
- 定位不把时间线锁死在某天。倒序时间线上滑查看更新记录，下滑查看更早记录，可以跨月、跨年；保留手动加载入口。
- “限定年月”是单独的严格筛选，适合只看某年或某月。与定位互斥，避免定位后不能滚到相邻月份。
- 正式记录按发生时间，草稿按草稿更新时间，回收站按删除时间排列。创建时间和公开时间仍独立保存。
- 记录菜单“加入浮窗”：加入右侧“浮窗记录”列表并打开独立阅读窗。可同时打开多条，拖动标题栏、拖动右下角调整大小、平铺阅读；正文分别滚动，无全屏遮罩。
- 关闭或收起仅关闭阅读窗，列表仍保留；刷新后可从列表重开。“移出浮窗列表”才删除列表项，且不删除原记录或其他记录中已保存的引用。
- 勾选列表内多条记录，可引用到新记录、当前正在编辑的记录，或搜索选择已有记录。编辑器内可移除关联，保存草稿和正式记录都保存引用。
- 浮窗是只读原文；引用保存稳定记录编号，不复制原文。原记录移入回收站后显示不可用提示，不展开其正文。不可跨用户引用，也不能引用自己。
- 小屏通过固定“浮窗记录”入口打开抽屉。

## 前端

请求统一在 `api/shareApi.ts`，服务端状态由 TanStack Query 管理。

`useShares` 使用双向 infinite query；分页参数包含 cursor 与 direction。每页20条，最多保留5页，即同时挂载至多100张时间线卡片，远端页面被移出后仍可通过反方向游标重新读取。追加或前插时记录首个可见卡片编号和屏幕位置，数据更新后补偿滚动偏移，避免阅读内容跳动。

`ShareFloating` 管理打开顺序、焦点层级、平铺与本地窗口位置；浮窗列表是后端持久数据，打开/关闭与坐标为当前页面状态。浮窗详情按编号延迟查询，不随时间线翻页重复载入。

`ShareEditor` 在本地编辑副本中维护 referenceNos，去重并防止重复添加；查看正式记录与恢复编辑草稿仍走原有隔离逻辑。关联信息与正文在同一次保存请求提交。

## 查询与持久化

- `SqlShareReadRepository` 使用参数化 SQL 和固定白名单排序列，数据库执行筛选、统计和 keyset 分页；不使用深 offset。
- 稳定排序为时间 DESC、record_no DESC。双向游标含时间、编号及筛选条件指纹，切换筛选不接受旧游标；所有查询固定当前登录用户。
- 定位首批读取目标日期结束前最近的记录；若此前没有记录，回退到其后最近记录。后续仅按游标连续读取。
- 列表读取摘要并移除富文本 document；详情只读取指定记录、至多50个关联及相关媒体。年月选项由数据库按当前状态生成，不从浏览器已载入页推导。
- 新增、编辑、删除恢复与媒体操作按编号加载；新增幂等通过用户+client_request_no索引查找，不扫描全部历史快照。标签删除只加载被该标签关联的记录及编辑副本；标签排序只读取标签元数据。
- 读查询和按编号加载采用 Spring NamedParameterJdbcTemplate，投影同步沿用 MyBatis；均位于 infrastructure 层，应用层不直接写 SQL。用户级写锁、记录版本与草稿版本继续生效。
- 浮窗列表每用户最多50条；一个记录最多关联50条，禁止重复、自引用、跨用户和新增已删除来源。已存在的失效引用可保留，避免保存其他修改时被阻断。
- 引用保存在记录与编辑副本 JSON 内。当前没有反向引用查询、引用内容快照或公开传播能力。

新增 Flyway：

1. `V202611031630__share_timeline_and_shelf.sql`：草稿/删除时间索引、双向查询索引、`share_float_item` 表。
2. `V202611031700__share_request_index.sql`：创建幂等请求编号与用户联合唯一索引。

服务重启后自动迁移，不能手动只改 JSON 或关系投影绕过应用服务。

## 接口增量

接口前缀 `/api/v1/shares`，需要登录，不接收客户端 owner。

| 接口                                            | 增量                                                                                                                   |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| GET `/records`                                  | anchorDate=YYYY-MM-DD、direction=older/newer；返回 previousCursor、nextCursor、anchorRecordNo、exactDate、matchedCount |
| GET `/records/periods`                          | 按当前 status 获取可用年份与月份                                                                                       |
| GET `/floating`                                 | 当前用户持久浮窗列表，含不可用标记                                                                                     |
| POST `/floating/save?recordNo=...&remove=false` | 幂等加入，remove=true移出                                                                                              |
| POST `/records/create`、`/records/save`         | record.referenceNos，最多50个                                                                                          |
| GET `/records/detail`                           | referenceNos、references、workingReferences；正式记录与草稿引用分别返回                                                |

## 验证与容量边界

真实 MySQL Testcontainers 覆盖：日期定位、跨月双向游标、同时间戳不重复、筛选游标不混用、引用与浮窗归属、失效来源、草稿隔离、幂等保存和数据迁移。

新增容量样本：同一用户30万条记录，分布7年。索引统计刷新后，本地定位请求约213ms；定位、双向读取、按月查询以及新增幂等重试组合约685ms。该结果仅为本机精简正文样本，不代表线上并发、长正文或含大量标签的性能承诺。

浏览器端验证：三条跨年原文同时打开、平铺、关闭后重新打开、引用到新记录并刷新回显、引用到已有记录；向上前插后可见卡片位置偏差小于1px；390px视口无横向溢出。

仍需按真实使用规模观察：关键词包含搜索和精确总数需要扫描匹配数据，年月聚合没有独立统计表；用户级写锁限制同账户并发写入吞吐；高频标签删除仍与被关联记录数量成正比。当前没有全文检索引擎、生产容量/并发压测和浮窗坐标跨设备同步。
