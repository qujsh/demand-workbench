# 成员资料与编号

基础身份称为“成员”，使用“成员编号、成员资料”；系统配置中的管理入口和页面保留“账号管理”，管理抽屉称为“管理账号”。稳定接口路径与权限编码保持兼容，例如 accounts.manage、userNo。

## 编号和昵称

- 对外编号 `memberNo` 格式为 `MEM-` 加至少六位十进制序号；不足补零，超过六位保留实际位数，不截断。数据库使用 VARCHAR(32)，支持 BIGINT 主键范围内的序号。
- Flyway V202611072200 依据 sys_user.id 回填 member_no，并建立唯一索引。已有标准 USER 编号由同一主键序号生成，原始 user_no、主键、会话和历史关联不修改。
- 新注册账号继续保留内部 user_no，同时由服务端生成 member_no；客户端不能修改编号。账号管理查询、成员定位、协作与成长调整兼容新旧编号。
- 新账号默认昵称为“成员”加手机号后四位。已有系统昵称和自定义昵称均不调整。
- 昵称为空的列表场景使用成员编号兜底，昵称仍可由本人编辑。

## 个人设置

页面依次展示个人资料、账号信息、我的身份、账号与安全。取消顶部重复身份卡片，头像和昵称仅在个人资料中编辑；成员编号、绑定手机号和账号状态集中放入账号信息。资料支持昵称（1–64字）、个人简介（最多500字、可清空）和头像。

发布资格归入我的身份。发布人、承接人可同时存在，管理角色独立显示，业务成长值与信用变化分开。等级规则在抽屉查看；安全记录默认三条、有效登录设备默认两条、成长信用记录默认三条，可展开现有接口返回的全部记录。

系统配置通过既有导航进入。需求列表中的“协作管理”进入 `/requirements/:requirementId/collaboration`，直接管理该需求成员，刷新可恢复编号；服务端既有负责人、管理员、编辑者和查看者规则不变。

## 头像上传与保存

- 复用私有对象存储和 media_upload 台账。上传场景 member_avatar，来源模块 identity，来源编号为本人内部ID；不依赖需求或分享权限。
- JPEG、PNG、WebP，单张最多5MB；云端定向Key、固定大小和MIME签发凭证，完成时重新查询云端对象元数据。
- 浏览器直传不携带业务Cookie。确认上传后取得媒体编号，点击“保存资料”才绑定；失败保留原头像，可重试。
- 保存时校验媒体归属、场景与完成状态。读取头像要求本人登录并返回短期签名地址；尚未提供公开成员主页头像接口。
- 移除头像只解除本人资料引用，不物理删除云端对象。
- `/api/v1/users/profile/save` 接收 nickname、bio、avatarMediaNo；省略新增字段保留原值，bio空字符串清空简介，avatarMediaNo空字符串移除头像。更新后同步本人资料缓存、成员列表及协作成员查询。

## 任务模块开关

“我的身份”默认收起；已有承接人身份的标题右侧展示任务模块开关。关闭确认仅显示“关闭任务模块？”，取消不修改状态。首次开启仍从 J1 公士开始；关闭只保存模块开关，保留身份状态、等级、成长值、信用及流水，再次开启继续使用原数据。身份受限且已关闭时禁止自行开启，服务端同样校验；发布人身份不受影响。

`POST /api/v1/users/contractor/module` 使用 `{enabled: boolean}` 保存当前登录账号开关，概览通过 `taskModuleEnabled` 回显。开关状态存储在 `contractor_profile.task_module_enabled`，旧承接人默认开启，变更记录操作审计。
