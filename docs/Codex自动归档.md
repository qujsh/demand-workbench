# Codex 自动归档试用版

本机已迁移到全局 demand-workbench-archive Skill，其他项目通过全局AGENTS.md默认使用同一归档入口。Skill位于 `~/.codex/skills/demand-workbench-archive/`，自带MCP客户端；当前项目不要与旧脚本重复提交。仅保存本轮主线程问答及明确附件，不读取历史对话或仓库内容、不采集工具日志、进度消息或模型内部推理。

全局配置位于 `~/.codex/demand-workbench-archive/config.json`；全局暂停/恢复执行Skill脚本的disable/enable。每项目的enabled=false仍可单独退出。后文保留旧项目版的组件及验证记录，用于已有队列排查；现行命令与规则以Skill为准。

现行离线策略：先gate、不传问答，整次检查最多约2秒；不可用就跳过本轮，按地址跨项目缓存60秒（命中不延长、不请求），到期只在下一轮检查。在线才带一次性availability_token调用publish。旧队列、失败及中断任务均不补传，启动服务后只保存后续新问答。

## 组件

- `.codex/hooks.example.json`：可选Hook示例；UserPromptSubmit 捕获本轮问题；Stop 冻结问题和最终回答并派生独立上传进程；SessionStart 尝试补传待处理任务。
- `scripts/codex_archive.py`：Python 3.9+ 标准库脚本，macOS 钥匙串读取密钥、本地 SQLite 队列、跨进程互斥、脱敏与幂等上传。
- `.codex/archive.local.json`：本机开关、MCP地址及既有上传辅助模块路径，Git忽略，不含密钥。配置示例在 `.codex/archive.example.json`。
- 图文上传复用后端仓库 `scripts/create_mcp_image_note.py` 的MCP客户端。需要该文件在本机存在；不修改笔记存储模型。

## 当前启用方式：助手主动归档，无需手动操作

当前本机配置为 `enabled=true, mode=assistant`。项目AGENTS.md已加入用户授权的持续规则：助手在每次最终回复定稿后、发送前，将本轮问题及完整最终回复通过标准输入交给 `publish` 命令，由独立进程后台上传。用户只需正常聊天，不需要信任Hook、不需要每次提醒。

```sh
# JSON由助手生成并通过标准输入传入，不要把密钥放在参数或JSON里。
/usr/bin/python3 scripts/codex_archive.py publish
```

输入结构为 `{question,answer,submission_id,session_id?,thread_title?,attachments?:[{source:"user"|"assistant",path:"/绝对路径/图片.png"}]}`。用户消息附图必须由助手显式传入attachments；图片路径本身不替代问题文字。thread_title首次提供后按会话缓存，改名时重新提供；取不到时不生成聊天标签，不用当前问题冒充聊天名称。submission_id为本轮唯一UUID，重试保持相同；session_id默认读取当前CODEX_THREAD_ID。脚本在落盘前脱敏，队列及网络逻辑与Hook模式共用。queued=true只表示入队；status中的done和recordNos才表示网站已保存。

归档提交发生在发送最终消息前，后台网络上传与消息发送独立，不能保证严格在界面显示消息后才上传。正文除脱敏和分段外使用即将发送的原文，不依赖读取Codex会话文件。这是助手遵循项目指令的流程，不是生命周期事件的强保证；中断、工具不可用或未执行项目指令时可能漏记。

本轮问题及同轮补充由助手明确提供，不上传所有历史会话、工具日志或内部推理。该模式只对当前项目聊天有效。用户说暂停、停止归档时，立即停止提交；本机配置enabled=false也会停止队列提交和后续上传。

## 可选Hook模式（当前未启用）

Hook示例已移至 `.codex/hooks.example.json`，不会被Codex自动加载；即便旧会话缓存了Hook命令，mode=assistant时该命令也不处理事件，避免重复归档。需要平台事件驱动时，才将示例复制为hooks.json、把mode改为hooks，并按照Codex自身要求审核信任。两种触发方式不应同时使用。

官方依据：https://learn.chatgpt.com/docs/hooks 。手动执行处理脚本的成功不能替代桌面应用生命周期自动触发验收。本机电脑控制工具禁止操作Codex应用，因此本次没有代操作Hook信任界面，也没有改写信任记录。

## 归档规则

- 每个项目＋session_id＋turn_id 生成固定任务编号；重复事件只保留一份任务。同一轮次一旦首次Stop入队即冻结，后续相同轮次的Stop不覆盖它。其他Hook或自动续跑导致同轮再次修改回答时，本版不会更新已冻结的笔记。
- 助手模式由助手提供本轮问题及补充；Hook模式用UserPromptSubmit事件捕获。不解析格式不稳定的Codex会话文件。
- 网页正文保存问题和最后助手回答；末尾追加来源、项目、聊天名称标签，例如 `#Codex #demand-workbench #查看后端MCP是否可用`。标签移除空白/#，截到30字，遵守后端每条10标签额度（优先保留正文原有标签）。对话归档不保存标题（title为空），分段关系仅由本地队列维护。会话及轮次编号只在本地保存，不再展示在正文中。网页正文按纯文本保存，Markdown/代码围栏不会复刻为Codex的富文本样式。
- 每段正文最多15000个UTF-16单元，给元数据留出空间；每段最多9张图。长文字、超过9张图分多条笔记，使用稳定的clientRequestNo和固定发生时间，重试不会重复创建。
- 图片来自本轮明确提供的attachments，保留用户/助手来源和列表顺序，相同本地路径只复制一次；也兼容问题和最终回答里的本地Markdown图片嵌入，例如 `![效果图](/absolute/path/image.png)` 或路径带空格时 `![图](</absolute/path/my image.png>)`。仅支持PNG/JPEG/WebP且单张不超过10MiB。不会扫描目录、自动截图或下载远程链接；会话内没有可读本地路径的附件不会自动上传。网站目前仍以笔记配图统一展示，来源保存在本地队列，暂不支持正文任意位置内嵌图片。Hook模式不会自动提取未定义的附件事件字段；本次用户附件能力以助手publish模式为准。
- 图片入队时复制到本地私有目录，之后原文件变化不影响重试。图片不可读、格式不支持或超限时，在归档正文附说明，文字仍归档。图片像素本身不会自动脱敏，用户明确排除的图片不得放入attachments或Markdown图片链接。
- 原始问题/回答在写队列前脱敏：dw_sk_、sk-令牌、Bearer令牌、私钥块，以及password/api_key/token/secret/cookie/密码/密钥等明确赋值。不保证识别所有自然语言、文件内容和图片里的秘密；需要更强脱敏时应扩展规则后再扩大范围。
- 被用户中断的轮次没有正常Stop时不会伪造最终回答。本版不支持中断内容归档。

## 查看状态与补传

在当前项目根目录执行：

```sh
/usr/bin/python3 scripts/codex_archive.py status
/usr/bin/python3 scripts/codex_archive.py retry
# 已连续失败5次的任务，明确重置后重试：
/usr/bin/python3 scripts/codex_archive.py retry --reset-failed
```

当前publish只进行本地捕获和派生独立进程，不等待网络。后台每次最多处理20条到期任务，并通过锁避免多个窗口重复处理。失败后延迟60/120/240/480秒等，之后在后续publish（Hook模式则是Stop、SessionStart）或手动retry时再次尝试；不是每分钟常驻扫描。单任务最多5次自动尝试，达到上限标为failed；`retry`跳过延迟但不自动重置失败上限。服务器恢复后下一次交互会尝试补传；没有新交互时可手动retry。

status仅显示任务状态、次数、异常类型和笔记编号，不回显正文和凭据。详细服务失败可按网站调用审计定位。401通常需更换密钥，403需检查当前账号权限；替换密钥会继续处理未完成任务，因此需要使用同一账号。

本地数据默认在 `~/.codex/archives/demand-workbench-<项目路径摘要>/`：目录权限0700、队列0600。保留已归档文本、配图和幂等进度，不自动删除；这是本机归档副本，不是凭据存储。网络上传失败后保留图片进度；上传成功但响应丢失时可能留下未关联媒体，不自动删除云端对象。

## 暂停和移除

把 `.codex/archive.local.json` 的 `enabled` 改为false，会停止新捕获及后续上传；已经开始的后台请求可能完成。若使用可选Hook模式，也可在Codex Hooks界面禁用本项目Hook。删除Hook配置不会删除网站已有笔记。本地副本和队列可在停止后台进程后自行清理，但丢失去重记录后重放历史轮次可能重复上传。
