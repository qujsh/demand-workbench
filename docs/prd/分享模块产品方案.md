# 构想台 · 分享模块产品方案

> v0.1｜2026-11-01｜待评审、未实现。本文新增规则均为建议默认值，不代表用户已确认。
>
> 来源：[分享体系讨论](https://chatgpt.com/share/6ae75c89-aa08-83ec-ac0d-6145a1fb32dc)。结合当前项目导航、路由、编辑器与媒体上传源码设计；未进行运行验收。

## 1. 目标与边界

用户通过记录生活、工作、想法和经历，自然积累成长轨迹；不要求填写履历表，不以记录数量评价个人能力。

已明确的方向：时间线组织记录、自由多标签、支持历史补录、公开与私密并存；分享独立于需求和任务；作品、成果和专业证明后续由专业模块承接。

本版建议：采用单页渐进编辑，不设置强制三步。任务发布的步骤偏好不直接套用分享。简单记录直接完成，附件和时间等选项按需展开。

| 阶段 | 范围 | 可交付结果 |
| --- | --- | --- |
| 第一版核心 | 文字、图片、草稿、编辑、移入回收站、时间线、搜索、平级标签、可见范围、记录详情、公开只读页 | 从记录到保存、回看、公开访问的完整闭环 |
| 第一版增强 | 视频与文件、标签合并、任务关联、记录热力图 | 在核心闭环完成后逐项增加 |
| 后续 | 嵌套标签、AI 推荐标签与经历提取、公开话题、评论点赞、推荐流、专业作品模块 | 不成为第一版上线依赖 |

第一版不提供简历页、能力评分、能力证明六大类表单；不引入内容运营数据看板。

“公开”第一版定义为：任何持有链接的人可以访问，只读，无互动；暂不代表进入推荐流或任务大厅。真正上线公开功能前必须明确平台内容审核责任与机制，未具备条件时只开放私密记录，界面不展示不可用的公开承诺。

## 2. 导航与页面

侧栏在“需求管理”之后新增“分享管理”。模块内用“记录”称呼单条内容，统一动作名称。

| 地址 | 页面 | 规则 |
| --- | --- | --- |
| `/shares` | 我的记录 | URL 保存关键词、标签、可见范围和状态筛选，刷新恢复 |
| `/shares/new` | 新建记录 | 独立页面，支持浏览器返回保护 |
| `/shares/:recordId/edit` | 编辑记录 | 只允许本人，能直接刷新恢复 |
| `/shares/:recordId` | 管理详情 | 本人完整内容及管理操作 |
| `/s/:publicId` | 公开只读页 | 独立阅读布局；非公开、删除、不存在均不暴露内容 |

标签管理与回收站使用抽屉，不增加主导航。列表浏览保留筛选与滚动位置，编辑或详情返回时恢复。

## 3. 我的记录首页

桌面结构：沿用全局侧栏；中央为可阅读的记录流；右侧约 240px 标签栏。中央内容建议最大宽度约 760px；窄屏收起标签栏，工具栏提供“标签”筛选入口。

```text
分享管理                                  [新建记录]
记录想法、分享经历，留住值得记录的时刻。

[今天有什么值得记录的？点击开始记录……]

[搜索记录……]  [全部记录 / 草稿]  [全部可见范围 v]
已筛选：#工作 ×                              清除筛选

2026 年 11 月                         我的标签
  11月01日  今天开始负责一个新项目       搜索标签
            正文摘要……                 #工作   12
            [图片缩略图]                #摄影    8
            #工作 #成长    仅自己可见   管理标签

2022 年 09 月
  09月12日  升职后的第一天……
            #工作          公开
```

首页不放大号统计卡。快速入口只负责打开编辑器，不再维护一套功能不同的输入表单。

**列表规则**

- 默认显示已保存的正式记录，包含公开和私密；草稿独立切换，不混入历史轨迹。
- 正式记录按事情发生时间倒序，按年月分组；同一时间按 ID 稳定排序。
- 草稿按最后修改时间倒序，避免历史补录草稿难以找到。
- 卡片展示时间、可选标题、最多约四行正文、最多三张缩略图、标签、可见范围；不重复放置所有操作按钮。
- 点击正文或标题进入详情；点击标签只改变筛选，不触发详情；图片点击打开图片预览。
- 每页 20 条，采用“加载更多”；加载失败保留已有内容并就地重试。
- 关键词搜索标题与正文；标签作为独立筛选。首版一次选择一个标签，可与关键词、状态及可见范围组合，条件之间为 AND。
- 搜索建议防抖约 300ms，切换条件重置分页；空结果提供清除筛选，不误显示首次使用引导。
- 首次无记录显示“记录第一件值得留下的事”；加载失败显示重试，不伪装成空列表。

## 4. 新建与编辑

```text
[返回] 新建记录                         保存状态

[给这条记录起个标题（选填）]
[写下想记录的事情……                  ]
[                                    ]
[图片缩略图，可排序 / 删除 / 重试]

[添加图片]     [# 添加标签]
标签：#工作 ×  #成长 ×

记录时间  今天 21:00 [修改]
谁可以看  [仅自己可见 v]

                              [保存草稿] [保存记录]
```

**字段与默认值（建议）**

| 字段 | 规则 |
| --- | --- |
| 标题 | 选填，最多 80 个字符；无标题列表直接显示正文，不自动生成虚假标题 |
| 正文 | 最多 20,000 个字符；支持段落、加粗、列表、链接；不支持任意 HTML |
| 内容有效性 | 正文或至少一个上传成功的图片必有其一；仅标题、标签不算有效记录；草稿允许不完整 |
| 图片 | 最多 9 张；JPEG、PNG、WebP；单张最多 10MB；支持进度、失败重试、排序与移除 |
| 标签 | 最多 10 个，每个名称最多 30 个字符；可不填 |
| 发生时间 | 默认创建时的当前时间；允许补录过去，不允许未来；首版精确到分钟，后续考虑只有年份或月份的经历 |
| 可见范围 | 默认仅自己可见，每次新建均如此，不沿用上次公开选择 |

限制在前后端一致校验；字数统一按 Unicode 字符计数，不能前端与后端各用不同计数口径。

**标签输入**：编辑区输入 `#` 时展示已有标签候选，支持键盘选择；选择后生成下方标签标记。未确认的 `#文字` 保持普通正文，不自动创建标签或公开话题。独立“添加标签”入口与正文 `#` 使用同一候选组件及同一标签集合；不提供重复配置区。

**保存与离开**

- 第一版使用明确的手动保存，不假装已自动保存。显示“有未保存的修改”“保存中”“已保存”等真实状态。
- 新建时“保存草稿”保留编辑状态；“保存记录”完成后进入详情，并提供返回列表。
- 已保存记录的编辑页主按钮为“保存修改”；不允许通过“保存草稿”意外把原公开内容下线。
- 公开选项下显示“保存后，持有链接的任何人均可访问”。选择公开后主按钮显示“公开发布”，首次公开需二次确认，成功后提供复制链接。
- 已有公开记录改为私密时明确提示原公开链接将不可访问；不承诺收回他人已保存的副本。
- 上传未完成或失败时禁止正式保存，提示处理对应图片；允许保存草稿，但只保存已上传成功的媒体，并在保存前明确说明未完成图片不会保存。
- 站内离开遇到未保存内容，提供“保存草稿并离开 / 放弃修改 / 继续编辑”；已保存记录提供“保存修改并离开”，避免生成重复草稿。浏览器刷新关闭使用原生离开提醒。
- 保存失败保留全部本地输入，可重试；重复点击锁定提交，服务端用幂等键避免重复创建。
- 多窗口编辑使用版本号校验；冲突时保留本地输入，提示查看最新版本，不静默覆盖。

## 5. 详情与公开展示

本人详情采用阅读布局：标题（有则显示）、发生时间、可见范围、完整正文、图片、标签；创建与修改时间收在辅助信息中。顶部操作为“编辑”，更多菜单放“复制公开链接”（仅公开记录）、“改为私密 / 公开发布”“移入回收站”。

公开页只展示作者公开昵称与头像、记录内容和发生时间。个人标签首版仅用于本人管理，不在公开页展示；公开页不暴露后台创建时间、草稿、其他私密记录、标签数量或邮箱手机号。无标题时不生成对外标题，页面元信息使用中性名称。

首版不提供公开个人主页或经历聚合页，防止把单条公开授权扩展为全部记录展示授权。

**媒体权限是公开能力的前置条件**：私密图片必须经过鉴权后签发短期访问地址，禁止使用永久公开 URL；公开转私密时撤销公开媒体访问并处理缓存。现有上传 API 绑定 requirementNo，不能创建虚假需求编号来复用，需新增记录上传场景与所有权校验。

## 6. 标签管理与回收站

标签抽屉支持搜索、新建、重命名、删除以及查看关联记录。名称去首尾空白，英文大小写不区分重复；同名标签在不同用户间互相独立。

- 重命名：关联记录同步展示新名称，不需要逐条编辑正文；正文中的普通 `#文字` 不进行批量替换。
- 删除：确认提示影响多少条记录；只解除标签关系，绝不删除记录；建议保留记录原修改时间，不让批量标签整理改变时间排序。
- 首版平级标签，嵌套与合并后续增加，避免在初版引入层级移动与重名冲突。
- 标签计数只统计当前用户未删除的正式记录，包含公开和私密，草稿不计；受列表搜索条件影响的结果数另行展示。

删除记录统一为“移入回收站”，二次确认后隐藏于所有正常列表、搜索和公开页。回收站保留 30 天，显示剩余天数，可恢复；恢复后默认私密，原草稿恢复为草稿。首版不提供手动永久删除，服务端到期清理记录及无引用媒体；原公开状态可保留在审计历史，不能在恢复时自动公开。

## 7. 状态与权限

草稿状态和可见范围是两个维度；草稿无论保存何种选项都不对外可见。

| 当前状态 | 操作 | 结果 |
| --- | --- | --- |
| 新建 | 保存草稿 | DRAFT，仅本人可读 |
| DRAFT | 保存记录 | SAVED + PRIVATE |
| DRAFT | 公开发布 | 审核通过或满足公开策略后 SAVED + PUBLIC |
| SAVED | 保存修改 | 保持现有状态及用户明确选择的可见范围 |
| SAVED + PUBLIC | 改为私密 | SAVED + PRIVATE，旧链接不可访问 |
| 任意未删除状态 | 移入回收站 | DELETED，保存删除前状态供恢复 |
| DELETED | 恢复 | 原草稿回到 DRAFT，否则 SAVED + PRIVATE |

若平台要求异步审核，审核状态单列，待审或拒绝内容不公开；公开编辑采用“当前公开版本 + 待审版本”，不能先公开后审核。本版公开上线流程需与后端、运营共同确定，不把 PUBLIC 字段当作审核机制。

本人可读写自己的记录与标签；其他人仅能读取可公开的版本。服务端从登录会话确定所有者，不接受前端 ownerId 决定权限。标签查询、媒体授权、搜索、统计与回收站同样受所有权限制。管理员角色不自动获得私密记录浏览权。

本版不进行 AI 经历提取，也不创建一个默认开启却无实际行为的授权开关。未来接入时单独说明用途和处理范围，私密内容不得因 AI 处理而被公开。

## 8. 数据与接口设计输入

以下为领域草案，接口路径及字段最终需和后端确认。

| 对象 | 核心字段 |
| --- | --- |
| Record | id、ownerId、title（可空）、body、bodyText、occurredAt、occurredTimezone、createdAt、updatedAt、status、visibility、version、publicId（可空）、deletedAt、previousStatus |
| RecordMedia | recordId、mediaId、sortOrder；媒体对象记录类型、大小、所有者与处理状态 |
| Tag | id、ownerId、name、normalizedName；ownerId + normalizedName 唯一 |
| RecordTag | recordId、tagId；组合唯一，同属一个用户 |

时间存储 UTC，发生时区单独保存，首版默认 Asia/Shanghai；列表按约定的展示时区进行年月分组，不能因运行服务器时区不同而跨日。

需要的接口能力：本人记录游标分页、搜索与组合筛选；读取详情；创建及带 version 更新；发布/转私密；软删除及恢复；标签 CRUD 与计数；记录媒体上传凭证、完成确认及受控访问；公开版本只读查询。所有变更校验所有权，媒体关联必须验证上传完成且归本人所有。

创建、保存、标签关联与媒体排序在服务端事务中提交；失败不留下半条正式记录。上传中的临时媒体由后端按过期规则清理，不依赖关闭页面时删除。

## 9. 与当前项目的实现衔接

- 新建 `src/features/shares/`，分别组织 api、hooks、components、pages、types，通过 index.ts 公开跨模块能力。
- 新页面接入现有 Router 和 App 布局，新增路由不能用根组件字符串状态模拟。
- 通过项目 HTTP 客户端请求，Zod 校验响应；列表详情用 TanStack Query，变更用 mutation；编辑缓冲使用局部状态。
- 复用现有主题变量、Ant Design 控件及 Tiptap 技术能力；需求编辑器是否提取共享基础编辑器需实现时判断，不直接跨功能导入内部文件。
- 当前 media 接口只有需求/任务场景且要求 requirementNo；复用上传传输逻辑前需明确记录上传协议与私密存储，不直接沿用永久 previewUrl。
- 不改已有需求拆解、任务发布流程，不新增依赖或改动固定版本。

## 10. 开发顺序与验收

1. 页面原型：记录列表、编辑、详情和标签抽屉，使用明确标识的演示数据；只验证目标页面，不声称真实保存成功。
2. 核心接入：身份隔离、记录 CRUD、草稿、时间、标签、搜索、软删除恢复；先完成私密文字闭环。
3. 媒体闭环：记录上传场景、图片鉴权、进度失败、关联与清理。
4. 公开闭环：内容审核方案、公开只读页、权限切换、媒体与缓存撤销。
5. 定稿后按项目完整检查等级验收，覆盖前端→接口→持久化→刷新回显；桌面与移动端均验证。

| 编号 | 必须证明的用户结果 |
| --- | --- |
| S01 | 新建私密记录保存后刷新仍存在，其他账号不可读，也搜不到或统计不到 |
| S02 | 今天补录 2019 年经历，正式记录位于 2019 年分组，草稿仍按修改时间排序 |
| S03 | 一条记录多个标签，重命名后展示一致；删除标签不删除记录 |
| S04 | 仅图片记录可保存；空正文且无图片不可正式保存；上传失败有明确处理入口 |
| S05 | 保存失败或并发冲突不丢输入；重复提交不会创建两条 |
| S06 | 草稿选择公开仍不能被公开访问；公开行为需明确触发 |
| S07 | 公开转私密后匿名正文与媒体均不可继续获取，缓存按约定失效 |
| S08 | 移入回收站后公开链接失效，恢复默认私密，不自动恢复公开 |
| S09 | 标签和图片点击不误进详情；返回列表恢复筛选和浏览位置 |
| S10 | 手机编辑器、标签抽屉、日期选择与离开提醒可操作，无裁切或横向溢出 |

## 11. 尚待评审的关键选择

- 单页渐进编辑作为分享默认交互，是否符合使用偏好；若保留步骤，应提供简单记录直达保存路径。
- 第一版是否立即开放匿名公开链接；需先明确公开内容审核和私密媒体撤销能力。
- 视频、文件、任务关联是否确需首发；当前建议后置，不影响文字图片记录主流程。
- 日期是否需要“仅年份 / 仅月份”：历史经历经常记不清具体日期，首版分钟精度只是简化方案，不能默默补造准确日期。

本轮为文档设计，未修改业务代码，未运行代码测试。文档审查范围为流程、状态、权限、数据与验收口径的一致性；不代表接口或页面已实现。
