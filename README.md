# 构想台前端

需求管理、AI 辅助分析、工作项拆解和任务发布的后台管理端。

## 技术栈

Vite + React + TypeScript + Ant Design + Tailwind CSS + TanStack Query + React Router。

## 环境要求

- Node.js 22
- npm 10 或更高版本
- 后端默认运行在 `http://localhost:8080`

## 启动

```bash
cd /Users/mainto/Documents/Codex/2026-09-30/https-chatgpt-com-share-6abcced2-9a98/demand-workbench
npm install
cp .env.example .env.local
npm run dev
```

终端会输出实际访问地址，默认优先使用 `http://localhost:4173`。

## 统一分类、草稿与正式发布版本

本 React 项目是当前使用的 B 端，B/C 共用共享后端 `/Users/mainto/javafile/demand-workbench-backend`。

1. 原任务发布表单直接配置标题、简介、共用分类、报酬、城市、预计投入、任务目标、交付和验收要求、图片／视频，不再重复填写“C 端公开配置”。
2. 分类来自同一字典，选择器旁“新增分类”允许登录用户创建，同名复用，新增后 B/C 均可使用。
3. 保存草稿只保存编辑内容。已发布任务继续展示当前正式版本，草稿中的内容和权限变化不立即对外生效。
4. 确认发布生成 V1，确认更新生成 V2 等；页面下方“发布版本”可只读查看历史。按单人编辑约定，后保存覆盖前一份编辑内容；每次正式发布仍生成新的历史版本。
5. 当前保存和发布统一为“所有人可见”，暂不提供受邀用户或等级范围配置；历史受限正式快照不会被自动公开，只有重新确认发布才按当前规则生效。
6. 取消发布结束招募，列表不再展示，原详情与历史仍可查看。图片支持 JPEG/PNG/WebP，视频支持 MP4，参考文件支持 PDF/ZIP；单文件最多50MB，最多8个媒体，视频需图片封面。

7. 发布预览和提交使用同一份公开内容，包含整份 AI 拆解工作范围、现金／物品／服务／组合回报、交付与验收、媒体、项目介绍和公开任务树；空的可选内容不展示空标题。
8. “放弃草稿”需确认：已发布时恢复当前正式版本，不改变取消状态或历史；首次发布前放弃会清空发布草稿并返回需求管理，原始需求和工作项不变。
9. 一份需求整体发布为一个任务。标题和简介只填写一次；项目结构仅保留工作范围树，整份已确认的 AI 拆解进入公开任务树，不公开内部状态、依赖或原始附件。已保存的任务树不会随内部编辑漂移，可点击“从当前 AI 拆解更新”重新带入。工作项目前不单独配置报酬或独立招募。

本轮完整详情新增迁移 `V202610261200__task_detail_interactions.sql`；历史版本继续可读，历史版本未包含项目任务时不虚构任务树。请手动重启共享后端加载新接口，已有前端开发服务通常会自动热更新。城市字段沿用城市编码与名称；C 端筛选读取当前公开现场／混合任务实际使用的城市，尚未新增全国行政区划字典。“为你发现”使用默认排序，暂无个性化推荐。

## 完整任务详情与招募（2026-10-27）

发布表单支持任务目标、协作说明和四类回报；整份 AI 拆解需逐项确认后才能发布，后端会校验工作范围与当前拆解一致。发布预览与 C 端章节一致，保留 B 端原有蓝色工作台风格。

发布后可暂停／恢复招募、查看申请并确认承接或拒绝。提交意向不占名额，确认承接才占用；后端事务保证并发不超额。已有意向后修改关键条件，必须先暂停招募再发布新版本，旧申请者需要重新确认；结束招募后本轮不提供重新开放。

保持原手动启动方式；后端重启会自动执行迁移。本轮未操作你的开发服务。详细验证记录位于 C 端 `docs/verification/task-detail/implementation.md`。
