# 从源码建立产品现状 PRD

读取根目录 AGENTS.md、相关 docs 约束，以及用户指定的后端仓库约束。先记录两端分支、提交和未提交修改；保留用户工作。历史方案仅用于发现待核对项，不能作为功能已交付的证据。

从当前可达路由建立功能地图，沿页面 → API → Controller → 应用服务 → Mapper/迁移和测试串联证据。核对数据归属、权限叠加、异步结果、正式内容与编辑副本、异常恢复。后端接口不等于前端闭环；将能力标为已实现、部分实现、未实现或待确认，并说明缺口。当前版本边界随代码核实，不永久沿用某版功能清单。

采用现有 PRD 与飞书文档技能编写。正文使用产品语言；截图、状态图和短表格解释使用方式，详细代码定位留在附录。区分业务对象、用户动作和技术调用，避免将三者画成同一种流程。

需要截图时使用当前真实页面和隔离数据库/测试账号，关闭无关真实付费服务，不能复用生产会话或绘制假 UI。先读页面结构，再定位操作；等待主要内容及数据加载结束，不能只等待侧栏文字。核对截图无白屏、加载态和秘密。图片裁剪或编号可辅助阅读，不改变页面事实。无法验证的页面明确标注。

Mermaid 源码与渲染图片一起保留，检查中文、字号、边界和箭头；宽图应拆分或改方向，不能靠缩小到不可读来塞进文档。

Markdown 主源放入 docs/product，素材放入其 assets/版本目录。记录代码基线、截图环境及验证限制，不产生第二份手工维护的 HTML 正文。项目专用脚本只在能复用且有明确收益时增加。

执行 codex mcp list 检查实际连接。优先已有飞书 MCP；也可用已授权 CLI 或浏览器，不猜工具。发布位置遵从本次用户指示；已有正文先读取并保护，避免覆盖历史 PRD。长文按章节串行发布；本地图片上传成正文图片，不能仅上传 Markdown 附件。保留原生标题、表格与说明；不要上传密钥或本地会话状态。

发布后重新读取主要章节、表格和图片数量，并在真实飞书页面查看开头、关键图片、最宽表格和结尾。记录未能完成的视觉验收项。交付飞书链接、主源、素材路径、实际图表数量和待确认项；不能把 API 成功写入等同于视觉验收完成。
